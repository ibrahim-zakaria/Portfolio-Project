# Test Output Structure

All generated test artifacts use the project-level `test-output/` directory. Maven build output uses the standard `target/` directory.

```text
test-output/
├── allure-results/       # Raw Allure results for the latest execution
├── full-report/          # Full Allure HTML report
├── allure-history/       # Persistent trend history
├── reports/              # Single-file Allure report
├── Logs/                 # logs.log for the latest execution
├── screenshots/          # Screenshots for the latest execution
├── videos/               # Reserved; recording backend is not implemented yet
└── executions/
    └── <execution-id>/   # Archived output for a completed execution
        ├── allure-results/
        ├── allure-report/
        ├── logs/
        ├── screenshots/
        ├── videos/
        └── single-file-report/
```

## Allure history lifecycle

1. At execution start, the listener cleans only the current working folders (`allure-results`, `Logs`, `screenshots`, and `videos`).
2. The previous `allure-history/` is copied into the fresh `allure-results/history/` folder before tests run.
3. At execution finish, Allure generates the full and single-file reports. The latest history is persisted back into `allure-history/`.
4. Current raw results, logs, screenshots, videos (if a backend is later added), and reports are archived under `executions/<execution-id>/`.

## Notes

- `target/` is the Maven build output directory and can be regenerated by `mvn clean test`.
- IntelliJ's `out/` directory is an IDE compiler output folder and is not used by the framework's Allure paths.
- Jenkins Allure Report > Results > Path must be `test-output/allure-results`.
- `ScreenRecordManager` does not currently record videos. Keep `recordTests=false` until recording is implemented.
- TestNG XML suite files are not used for normal execution; use Maven `-Dtest`, `-Dgroups`, and `-DexcludedGroups` parameters instead.
